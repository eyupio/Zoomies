# ZF-230 Catalog, provenance guard and command generator: implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One machine-readable catalog of every problem code and Kennel check, with what to do and how to see it worked, served from the docs site and the controller; a guard that keeps third-party names out of the tree; and a command reference generated from the binary.

**Architecture:** A new pure package, `internal/catalog`, builds the catalog from two sources that already exist, the Markdown tables in `docs/problem-codes.md` and `kennel.Checks()`, so no problem-code struct table is introduced. A `go:build ignore` generator writes the result into the package as an embedded `catalog.json`, which the API serves and a mkdocs hook publishes; a test rebuilds it and fails when the tracked file is stale, which is how every other generated file in this repository is kept honest. The CLI gains one introspective command whose output is the skills' reference file.

**Tech Stack:** Go 1.27 standard library only (no JSON-schema library: a Go test enforces the schema's constraints and the schema file is published for other readers), `gopkg.in/yaml.v3` where it is already used, mkdocs hooks in Python, the existing OpenAPI generators.

**Spec:** `roadmap/agent-readiness.md` section 3, with the ground rules in section 2.

## Global Constraints

- British spelling in prose; comments say *why*; `--` in code comments, `—` in Markdown; commit messages are imperative sentences in sentence case, no prefix.
- No new dependency. `docs/dependencies.md` is enforced by review.
- SQL only in `internal/store`; `internal/api` is transport only; `internal/kennel`'s evaluator stays pure (`boundary_test.go` allows only the standard library and no clock).
- A new setting, route or command arrives with its docs row: `docs/api-surface.md` for a route, `docs/cli.md` for a command (`TestEveryCommandIsDocumented` checks top-level names).
- Generated files are regenerated by their tooling, never edited: `go run internal/api/gen_openapi.go`, `make openapi` (needs `npm ci` in `web/` first), `make generate`.
- The clean-room rule (spec 2, 0.1): no third-party product, skill, command or rule-prefix names anywhere in the tree or in commit messages. The guard's own term list is supplied by the owner out of band and is **never** written whole into any file.
- Rule IDs: problem codes keep theirs; check codes are `area.name` as the registry writes them. The catalog's `id` is the code verbatim.
- `kennel.Version` is bumped only when a check's meaning or wording changes; adding `Fix`/`Verify`/`Docs` to the registry does not change a finding, so it is **not** bumped here.
- Before every push: `make build-nogui`, `make fmt`, `make lint`, `make test`, `go mod tidy` leaves `go.mod`/`go.sum` unchanged.

## Review Focus

1. A problem-codes table row whose code cell holds two codes or a code with a trailing qualifier (e.g. `` `security.disable_auth` `` with "on loopback" prose in the severity cell) must produce one entry with the first code and the severity text verbatim, never a parse failure. Pinned in Task 1.
2. A row in the *What the status page says* table repeats a code already in a runtime table; the catalog must hold each code once, with the status sentence attached as `status_sentence`, never a duplicate entry. Pinned in Task 1.
3. `GET /api/v1/catalog` must answer for a viewer and must not depend on `kennel.enabled`; a controller with Kennel Club off still serves the checks. Pinned in Task 4.
4. `zoomies commands` must not print anything a help text would not already print: no environment, no paths from this machine. Pinned in Task 6.
5. The provenance walk must skip `.git`, `web/node_modules`, `internal/api/webdist` and binary files, or it will take minutes and fail on a `.woff2`; and it must still scan `.github/workflows` and `roadmap/`. Pinned in Task 7.

      DocsMD         string    `json:"docs_md"`
  }
  type Catalog struct {
      Version       int     `json:"version"`        // 1
      GeneratedFrom string  `json:"generated_from"` // commit, "" in tests
      Entries       []Entry `json:"entries"`        // sorted by kind then id
