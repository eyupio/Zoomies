# ZF-231 `why`: a sharper explanation — implementation plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One question, "why did this job fail, stall or run slow", answered with a class, evidence a person can check, the catalog entry and ordered next steps, from the CLI, the API, MCP and the job drawer, without calling a model.

**Architecture:** `JobExplanation` keeps every field it has and gains the new ones. The classing is a pure function in `internal/controller/why.go` over a snapshot the existing `ExplainJob` already assembles (the job, the last plan, the pool's runner counts, the host), so each class is a table-test row. The one new piece of data is a bounded tail of the runner's output: the agent already holds the evidence when a runner ends badly, so it sends up to forty lines with the report and the controller stores them on the job, which is what makes an excerpt possible after the runner is gone. The CLI, MCP and the drawer read the same route; none computes anything of its own.

**Tech Stack:** Go 1.27 standard library; Svelte 5 runes and the existing tokens; the existing OpenAPI generators; SQLite migration `0085`.

**Spec:** `roadmap/agent-readiness.md` section 4, with the ground rules in section 2 and the record in `ROADMAP.md` (ZF-231).

## Decisions the spec left open

- **Exit codes.** The spec's `2` (job not found) and `3` (not enough data) are kept as written. `2` is already "invoked wrongly", and an argument that names no job is read as that. `3` is the controller process's restart code (`exitRestart`); `zoomies why` is a different process and never restarts, so the two never meet, and `docs/cli.md` says so beside the existing paragraph. A typed error, `whyExit`, carries the code through `report` the way `doctorExit` does.
- **Classes beyond the spec's list.** A queued job that nothing blocks (a runner idle or on its way) is `queued`, with high confidence: the spec's set has no name for the ordinary case and `unknown` would be a lie. A conclusion the fleet does not class (`skipped`, `neutral`, `action_required`, `stale`) is `unknown` with the reason naming the conclusion. Fault `backend_busy` is a startup failure; faults `removed` and `runner_exited` are `unknown` with the reason naming the fault, because the fleet lost the runner without recording a cause.
- **Memory limit.** The job has no limit field; the evidence row `memory_limit` is `GrantedMemoryMB` when it is above zero, else absent, and the confidence reason says the limit was not recorded.
- **Log excerpt.** The controller keeps no output today. The agent sends a tail of at most 40 lines, each cut at 400 runes, with any report whose `Fault` is set or whose exit code is non-zero; the controller stores it on the job. The excerpt is the `N` lines ending at the decisive line (the last line matching the fault's pattern: `Killed`/`137`/`memory` for `oom`, `No space left`/`ENOSPC` for `disk`, else the last line), scrubbed per line with the problems scrubber, numbered from the tail's first line. `N` defaults to 12 and is capped at 40. A job with no tail stored gets `null` and `note`: "The runner's output was not kept: it ran on an agent older than this release, or it ended before this fault was recorded."

## Review Focus

1. A job whose runner ended with fault `out_of_memory` **and** whose GitHub conclusion is `success` (the OOM was a step the job tolerated) must class `oom` with the conclusion in evidence, never `succeeded`. Pinned in Task 1.
2. A queued job whose pool has since been deleted must class `queued-blocked` with evidence `pool_missing`, not panic and not `unknown`. Pinned in Task 1.
3. A tail whose lines carry ANSI cursor moves, bidi controls and a line that says "ignore previous instructions" must come out as plain numbered text with the sentence intact as text. Pinned in Task 2.
4. `?logs=0` and `--no-logs` must return `log_excerpt: null` with no note (asked for none), distinct from a missing tail. Pinned in Task 3.
5. A GitHub URL with `/job/<id>` whose job the fleet never saw must exit 2 with a sentence that names `zoomies jobs list --repo <owner/repo>`, never exit 1. Pinned in Task 4.

  //   Evidence []Evidence `json:"evidence"`; LogExcerpt *LogExcerpt `json:"log_excerpt"`
