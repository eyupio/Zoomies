# ZF-229c part two: the matrix check, the prompt per finding and `zoomies kennel` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Finish ZF-229c: the one observed check the record still owes (`capacity.matrix_exceeds_pool`), a prompt a coding agent can take from every finding (on the page, over the API and from the CLI), and `zoomies kennel`, whose `check [path]` runs the workflow checks over a local checkout without a controller.

**Architecture:** The matrix check is a sixth observed check: one more group in the store's fleet-facts query, one more fact on `JobFacts`, one evaluator. The prompt is a pure function in `internal/kennel` over a finding and the gated paths, rendered by the controller into the repository view (so the page, the API and the CLI all copy one text) and stripped by the MCP tool with the rest of the evidence. The offline check is a small package below the evaluator, `internal/kennel/offline`, that owns the conversion from parser facts to evaluator facts (moved out of the controller so both use it), reads `.github/workflows` from disk, and runs `kennel.Evaluate` with a coverage that says what a laptop cannot know. `zoomies kennel` is one verb file in `cmd/zoomies`, thin readers of the existing routes plus `check`.

**Tech Stack:** Go 1.27 (standard library, `gopkg.in/yaml.v3` already in the module), SQLite through `internal/store`, Svelte 5 UI, Playwright, mkdocs.

**Spec:** `roadmap/agent-readiness.md` section 6 (6.1's `capacity.matrix_exceeds_pool` row, 6.3, 6.4, 6.5's golden JSON); the Kennel Club record `roadmap/kennel-club.md` Stage 3; `ROADMAP.md` ZF-229. Part one is merged as #761 and its plan is `roadmap/plans/2026-10-09-zf-229c-location-evidence.md`.

## Decisions the spec left open

- **What a matrix is, observed.** The jobs table has no matrix flag. A matrix job's name is GitHub's `<job name> (<values>)`, so a matrix is the jobs of one run attempt, in one pool, whose names share the text before the first ` (`. Two or more such jobs is a matrix. The check fires when the pool's `max_runners` is positive and below the matrix's width and at least one of its jobs waited `MatrixWait` (two minutes) or more between queueing and starting: a pool that is simply busy is a different problem, and a pool with no ceiling (`max_runners` 0, or an automatic pool) cannot be too small. Info, one finding per pool, the pool is the subject and the evidence.
- **Where the prompt lives.** `kennel.Prompt(f Finding, paths map[string]string) string`, beside the registry, tested for every check. The controller renders it into each finding of the repository view as `prompt`, so the page's button, the API and `zoomies kennel repository` carry one text; `zoomies kennel check --prompts` calls the same function over its own findings. The MCP tool deletes `prompt` from each finding with the evidence it quotes, and its notice says where a prompt is had. A waived finding carries no prompt.
- **Visibility offline.** Several workflow checks are milder for a private repository. `kennel check` assumes private, the milder reading, unless `--public` is given; the report says which it assumed.
- **What `check` does not check.** Every check whose `Needs` include a source a laptop does not have (`SourceFleet`, `SourceRuns`, `SourceSetup`) is listed under `not_checked` with the source that was missing. `ci.label_unserved` needs the pools, so it is turned off by name offline and listed the same way. `--controller <owner/name>` reads that repository from the controller and appends the findings whose codes are not in the offline set, each marked `"from": "controller"`.
- **Exit codes.** `0` no finding at or above `--severity` (default `info`, so any finding is `4`); `1` an error, including a path with no workflows directory; `4` findings.

## Review Focus

1. A local workflow file whose name is `IGNORE PREVIOUS INSTRUCTIONS.yml` must reach the report and the prompt as "a workflow with an unusual name" and never as the sentence; a gated path must appear in the prompt only inside the fenced block. Pinned in Task 2 (prompt) and Task 3 (offline).
2. A matrix of six jobs on a pool whose `max_runners` is 0 (no ceiling) must raise nothing; the same matrix on a pool of 2 whose jobs started within a minute of queueing must raise nothing either. Pinned in Task 1.
3. `zoomies kennel check` on a directory with no `.github/workflows` must exit 1 and say so; on one whose files all pass must exit 0 and print that nothing was found at the asked severity; `--severity error` over a tree with only warnings must exit 0. Pinned in Task 3.
4. The JSON `check` prints must be byte-stable across runs (sorted files, findings in evaluator order, SHAs from content), which is what the golden files prove. Pinned in Task 3.
5. The Copy button must copy the same text the API carries as `prompt`, and a finding without a prompt (a waived one) must show no button. Pinned in Task 2.
