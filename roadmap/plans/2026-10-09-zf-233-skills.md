# ZF-233: skills for a coding agent Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Two self-contained skills a coding agent installs from this repository, `skills/zoomies/` and `skills/zoomies-kennel/`, with a test that keeps them honest and the install documentation.

**Architecture:** Each skill is one `SKILL.md` with the frontmatter the common installers read (`name`, `description`), beside the generated command reference that `make generate` already keeps equal to the binary. A test in `internal/docs` holds every skill to the same rules: frontmatter present and matching its directory, no dangling reference, no absolute path, a length cap, and every `zoomies` command the text names existing in the binary; a second test holds the `zoomies` skill to naming every command that changes something. The docs say how to install them with the path `eyupio/zoomies`.

**Tech Stack:** Markdown with YAML frontmatter; Go tests in `internal/docs` (standard library plus `gopkg.in/yaml.v3`, which the package already imports); `go run ./cmd/zoomies commands --output json` as the source of truth for command names.

**Spec:** `roadmap/agent-readiness.md` section 7 (and 3.6 for the pinned reference); `ROADMAP.md` ZF-233 and gate row 15 ("The pinned reference matches the binary; a smoke test in two agents is recorded").

## Global Constraints

- British spelling in prose; no spaced em dash anywhere (`internal/docs/no_em_dash_test.go` walks the whole tree, `skills/` included); commit messages are imperative sentences, no prefix; no model identifiers in anything pushed.
- Product skills live under `skills/` at the root and never under `.claude/skills/`, which holds the repository's maintenance skills.
- `skills/zoomies/reference.md` is generated: never edited by hand; `make generate` rewrites it and `TestTheCommandReferenceMatchesTheBinary` (`cmd/zoomies`) holds it equal to the binary.
- A skill names a command only as the binary has it. The test derives the command list from `go run ./cmd/zoomies commands --output json`, never from a copy.
- Before every push: `make build-nogui`, `make fmt`, `make lint`, `go test ./internal/docs ./cmd/zoomies`, `go mod tidy` leaves `go.mod`/`go.sum` unchanged, `make generate && git diff --exit-code` (the catalogue's `generated_from` line aside), `python3 -m mkdocs build --strict`.

## Decisions the spec left open

- **Frontmatter.** `name` (equal to the directory name) and `description` (one paragraph, 20 to 1024 characters, written for the installer's listing: what the skill is for and when to use it), the two keys every installer reads, and nothing else: an extra key one installer rejects would break the others.
- **The mutating list is checked, not remembered.** The test holds a closed set of verbs that change something (`create`, `edit`, `delete`, `enable`, `disable`, `prewarm`, `import`, `import-env`, `drain`, `cordon`, `uncordon`, `apply`, `rerun`, `set`, `unset`, `passwd`, `reset-two-step`, `revoke`, `purge`, `rotate-secret`, `connect-proxmox`, `add`, `pause`, `resume`, `start`, `stop`, `restart`, `update`, `down`, `join-token`, `recheck`) and the top-level commands that do (`init`, `update`, `upgrade`, `uninstall`, `restore`, `import`, `tune`, `demo`), and asserts the `zoomies` skill names every command or subcommand whose name is in the set, so a new verb fails the test until the skill says to ask before running it. `check` under `updates` and `config` is a read and is not in the set.
- **Preflight wording.** The skill says to run `zoomies status` and to stop on failure with one of three sentences, chosen from the error: "zoomies is not installed" (command not found), "zoomies is not signed in" (the client says no credentials, or a 401), "the controller is not reachable" (a transport error). The exact words are in the skill, quoted, so an agent says the same thing every time.
- **The smoke test.** Gate row 15 asks for a smoke test in two agents. This session is one agent (Claude Code); the skills are exercised here by installing them into a temporary skills directory and following each once: `zoomies` against the demo controller (`zoomies demo`), `zoomies-kennel` against this repository's own workflows. A second agent is not available in this environment; the pull request records that and asks the owner to run the second.

## Review Focus

1. A skill that names a command the binary does not have (a typo, a renamed verb) must fail the test, with the name in the message. Pinned in Task 1.
2. A new subcommand whose name is in the mutating set must fail the test until the `zoomies` skill lists it. Pinned in Task 1.
3. `skills/zoomies-kennel/SKILL.md` must tell the agent to make no edit without a selection, and to say that nothing left the machine; the test asserts the sentences. Pinned in Task 2.
4. A relative link in a skill to a file that is not in the skill's directory must fail the test (an installer copies the directory, nothing else). Pinned in Task 1.
5. The install documentation names the path `eyupio/zoomies` and the two skills by their directory names; a test holds `README.md` and `docs/cli.md` to naming both. Pinned in Task 3.

### Task 1: the `zoomies` skill and the test that holds every skill

**Files:**
- Create: `skills/zoomies/SKILL.md`
- Create: `internal/docs/skills_test.go`
- Test: `go test ./internal/docs -run Skill`

**Interfaces:**
- Produces: the test helpers `skillDirs(t) []string` (every directory under `../../skills` holding a `SKILL.md`), `skillText(t, dir) (front map[string]string, body string)`, and `commandNames(t) map[string]bool` (every `zoomies <cmd>` and `zoomies <cmd> <sub>` from `go run ../../cmd/zoomies commands --output json`, whose items carry `name` and `subcommands[].name`). Task 2 adds a skill and relies on the same tests passing over it.

- [ ] **Step 1: Write the failing tests** in `skills_test.go`:
  - `TestEverySkillHasTheFrontmatterTheInstallersRead`: for each skill dir, the file starts with `---`, parses as YAML, `name` equals the directory's base name, `description` is 20 to 1024 characters with no newline.
  - `TestEverySkillIsSelfContainedAndShort`: no `](` link or backticked path that names a file outside the skill directory or that does not exist in it (Review Focus 4); no `/home/`, `/Users/`, `/root/`, `/tmp/` or `C:\`; at most 250 lines.
  - `TestEveryCommandASkillNamesIsOneTheBinaryHas`: every match of `zoomies [a-z-]+( [a-z-]+)?` in the body is in `commandNames(t)`, trying the two-word form first and the one-word form second; the failure names the text (Review Focus 1).
  - `TestTheZoomiesSkillAsksBeforeEveryCommandThatChangesSomething`: with the verb set from Decisions, every `zoomies <cmd> <sub>` whose `sub` is in the set, and every top-level command in the set, appears in the body of `skills/zoomies/SKILL.md` under the heading `## Before changing anything` (Review Focus 2); and the body contains the three preflight sentences from Decisions, quoted.
- [ ] **Step 2: Run** `go test ./internal/docs -run Skill`; expected FAIL (no `skills/zoomies/SKILL.md`; `commandNames` builds).
- [ ] **Step 3: Write `skills/zoomies/SKILL.md`**: frontmatter; *Routing* (live fleet, jobs and capacity: the CLI, or MCP when connected; changing GitHub state: `gh`; workflow files: the `zoomies-kennel` skill); *Preflight* (`zoomies status`, the three sentences); *The reference* (`reference.md` beside this file is every command with its help, generated from the binary; read it before guessing a flag); *Reading before writing* (`zoomies status`, `zoomies problems list`, `zoomies jobs list`, `zoomies why <job>`, `zoomies pools list`, `zoomies hosts list`, `zoomies kennel overview`); *Before changing anything* (the list, each line `zoomies <cmd> <sub>`: show the command, say what it changes, ask, run only on a yes, read the object again afterwards, in the spirit of the MCP tools' `expect` argument); *What it never does* (no `--insecure`, no token in a command line that reaches a log, no `uninstall` or `restore` without the owner).
- [ ] **Step 4: Run** `go test ./internal/docs -run Skill`; expected PASS.
- [ ] **Step 5: Commit** `Add the zoomies skill, and hold every skill to naming only commands the binary has`.
