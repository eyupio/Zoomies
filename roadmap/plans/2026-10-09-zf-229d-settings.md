# ZF-229d: repository settings and required checks, Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Kennel Club reads the repository settings that govern a workflow's token and a fork's approval, and the required checks that gate merges, and says where they put CI or the fleet at risk. Four findings, one new area, an opt-in switch, and a Protection tab. Fixes are links to the exact setting on GitHub; **nothing is ever written**.

**Architecture:** Two new sources, `settings` (the Actions-permission endpoints that a finding reads) and `protection` (classic branch protection plus the active rules for a branch), each read by an optional reader behind one new platform setting, `kennel.settings_checks`, which defaults to off like its three siblings. The evaluator stays pure and gets counts, never names: the controller compares the required checks it kept with the job names the fleet saw and hands the evaluator three numbers. The App's Administration read is asked for at creation, as an option that defaults to no, or added later on GitHub; a 403 is the `denied` coverage state and names the permission.

**Tech Stack:** Go 1.27, go-github v88 (every call below exists in it, including `ErrBranchNotProtected`), SQLite through `internal/store`, Svelte 5, Playwright, mkdocs.

**Spec:** `roadmap/kennel-club.md` Stage 4, section 4 (permissions and consent) and Appendix A. This plan corrects that text where it differs from the code on `main`; the differences are listed in "Decisions the record left open or got wrong". Stages 1 to 3 are merged (#661 to #767); the Stage 5 plan is a separate document and is not started.

## Global Constraints

- British spelling in prose; comments say *why*; no em dash and no `--` stand-in anywhere; commit messages are imperative sentences with no prefix; no model identifiers in anything pushed.
- Only `exposure.*` checks may be errors. A check's code prefix is its area, so the required-check code forces a new `protection` area. Every check has a positive fixture in `positives`, a Fix and a Verify under 240 characters, a generated heading on `docs/kennel-club.md` and an entry in the closed list in `registry_test.go`.
- `internal/kennel` stays pure: `boundary_test.go` allows `regexp, slices, sort, strconv, strings, time` and no clock. No check name, branch name or setting text reaches a sentence; the evaluator is given counts, and the hostile snapshot in `hostile_test.go` is extended, never weakened.
- **No write request is ever made.** Appendix A's "never" row is enforced by a test in this stage, not promised: every request the Kennel loop makes in the controller test is a `GET`.
- `internal/store` is the only package that writes SQL, and reads through `s.read`. No migration is needed: new per-source state lives in the watermark document, as workflow and setup state do.
- A schema change arrives with `go run internal/api/gen_openapi.go`, `make openapi` and its `docs/api-surface.md` row; `make generate` regenerates the catalogue and the check list. `kennel.Version` becomes 7 and the golden JSON under `cmd/zoomies/testdata/kennel` is regenerated with `-update` and reviewed line by line.
- Before every push: `make build-nogui`, `make fmt`, `make lint`, `make test` (the controller package needs `-timeout 40m` on this machine), `make generate && git diff --exit-code`, `python3 -m mkdocs build --strict`, and, for any UI slice, the Playwright kennel spec after `make build VERSION=dev`.
- Each slice is one pull request, mutation-checked as ROADMAP rule 14 says, and carries the documentation that its change makes true.

## Decisions the record left open or got wrong

Read against `main` (`f2cea17e`), not against the record.

1. **There is no permission flow to extend.** Stage 3 shipped as a Zoomies setting, `kennel.workflow_checks`, and nothing else: no `KennelWorkflows` manifest option, no requested-versus-granted split in `AppInfo`, no `MissingForKennel`, no use of `CanReadContents` by a background Kennel read. A missing Contents permission answers 404 and shows as `unavailable`. Stage 4 follows what was built: a setting gates the read, and the manifest option is an addition for new Apps (Task 6), not the gate.
2. **One switch, `kennel.settings_checks`.** Platform-owned, off by default, live, and named in `kennelSettingsChanged`. It gates both new sources. It is not called `repository_settings`, which sits beside the existing `repository_setup` and would be mistaken for it. An administrator who has not accepted Administration read on the installation sees `denied`, "Needs the App's Administration permission", and nothing else.
3. **Two sources and one new area.** `settings` and `protection` are separate so the page can say that the Actions settings were read and the protection was not. The area is `protection`, holding only `protection.required_check_never_reports`; `token.default_write` stays in `token`, and the two fork findings stay in `exposure`. The design table calls the pinning check `ci.target_checkout_pr_head`; the code is `exposure.target_checkout_pr_head`, and this stage does not touch it.
4. **`kennelDisabled` turns the whole `token` area off with the workflow switch.** That would also switch off `token.default_write`. The `token` and `ci` areas are no longer disabled as areas by `workflow_checks`; the loop that already disables a check by the source it reads does it, so a check is off exactly when a source it reads is off. `kennel_operations_test.go` hard-codes the old map and changes with it.
5. **A visibility-scoped check names its source as `Conditional`, not `Needs`.** `exposure.fork_approval_weak` applies to public repositories and `exposure.private_fork_secrets` to private ones. A source in `Needs` would skip the check, and mark the repository `partial`, wherever the check does not apply. `exposure.fork_code_ran` and `SourceRuns` are the precedent.
6. **The downgrade must not declare its source.** `token.permissions_unset` says "that default has not been checked". With the settings read it is silent when the default is read-only and says the default is write when it is. It reads the `settings` coverage state inside its evaluator and does not put the source in `extra`, or `Evaluate` would skip the check whenever settings are off, denied or unread, which is the opposite of the intent. `TestWhatTheCatalogueSaysACheckReadsIsWhatItAsksFor` stays satisfied because `extra` and `Conditional` stay equal.
7. **404 means three things and the reader tells them apart.** Classic protection answers 404 "Branch not protected" when there is none, which is normal and not `unavailable`; go-github returns `ErrBranchNotProtected` for it and the reader checks for it before the shared `classify` turns it into `ErrNotFound`. A 404 on a settings endpoint is a GitHub that lacks it, so `unavailable`. A 405, which `classify` does not map and which would become `error` and retry every thirty minutes, is mapped to `unavailable` inside the Kennel reader and not in the shared code. A 403 is `denied`.
8. **Required-check judgement lives in the controller.** The evaluator is handed `RequiredChecks`, `NeverReported` and `JobsSeen`, nothing named. The controller keeps the pinned required-check contexts in the watermark, and each local evaluation asks the store one bounded question (below). A required check is judged only when it is pinned to the GitHub Actions app, id 15368, a constant with its source named; a check with no app, or another app, is counted as skipped and never judged. Fewer than twenty jobs seen in the window is *unknown*: a delivery gap looks identical to a missing check. The names are never echoed; the finding carries the numbers and a link to the setting.
9. **Jobs seen are not only the fleet's.** `Ran` counts jobs with a runner and so excludes GitHub-hosted jobs, which would make a required check that hosted runners produce look like one that never reports. The webhook ingest records every `workflow_job` for a covered repository, so the new store question counts the unfiltered set.
10. **The links carry no repository text.** The Fix is a link to the exact setting, built in the UI from a fixed map of finding code to path suffix and the repository's web address. The evidence kinds stay `pool`, `run`, `file`. Task 5 first looks at how the repository page links to GitHub today and reuses that; if it holds only the API host, the repository view gains a web address derived with `WebURLForAPI` (`internal/github/client.go`, near line 452) and that is a schema change with its own regenerated files.
11. **The allow-list tests do not read Appendix A.** `KennelEndpoints` (a Go list) is compared to the recorded requests by `TestKennelClubCallsOnlyTheEndpointsItDocuments` and `TestEveryRequestKennelClubMakesIsOneItDocuments`. Neither turns on the opt-in reads, so the git tree and blob entries are listed but never exercised, and neither asserts that no request was a write. This stage extends the normaliser (`actions/permissions[/...]`, `branches/{b}/protection`, `rules/branches/{b}`, where a branch such as `release/1.0` adds a segment), enables the switches in the controller test, and adds the all-`GET` assertion.
12. **Cost is counted.** A 2xx settings response is cached by ETag and a 304 replays it. A 404 or a 403 is never cached and is a full-cost request on every refresh, so classic protection on a repository with none costs one every time. Each repository makes four to six requests per refresh, once a day by default, each preceded by the budget's `take()`. A denied source retries on the ordinary interval, not the fifteen or thirty minutes of `held` and `error`.
13. **A new source must be added in several places the compiler cannot find.** `KennelSources` in `kennel_views.go` (a hard-coded list the pages iterate), `okCoverage()` in `fixtures_test.go`, `allSources` in `coverage_test.go`, `Source.Permission()`, `Label()`, `Explain()`, `sourceWords` in the offline package (its default prints the raw word), and the `KennelSource` and `KennelCatalogueEntry.area` enums in `api/openapi.yaml`. The area enum is already missing `guidance`; it is corrected in the same change. `internal/catalog` switches on area for a check's detection, category and cost, and a `protection` area otherwise falls through to *runtime* and *configuration*, which is wrong for a setting read; the switch and its test are extended.

## Debts found on the way, not in this stage

- `docs/quickstart.md` (about line 169), the installer's `notePermissions` ("no repository permissions: this App cannot read or change code") and the Connect dialog's text were not revised when Stage 3 started reading private repositories' workflow files, which needs Contents read. They are untrue today and are not made worse by Administration read, which is not access to contents. A separate documentation pull request should correct them; it is not folded in here.
- A missing Contents permission shows as `unavailable` with the wording "This GitHub does not offer it", which is misleading. Fixing it means telling a 404 for a missing permission from a 404 for a missing endpoint, and is a Stage 3 follow-up.

## Review Focus

1. A classic protection 404 is *no required checks from this source*, never `unavailable`; a repository whose rulesets alone require checks must not be judged as unprotected. Pinned in Task 1 and Task 3.
2. A check with no app, or an app other than 15368, is never judged, and fewer than twenty jobs seen is unknown. A required check whose name is in the output, in a finding, a prompt, a log or the MCP tools, fails the build. Pinned in Task 2 and Task 3.
3. A public repository with settings denied must not go `partial` because of `exposure.private_fork_secrets`, and the reverse. Pinned in Task 2.
4. `workflow_checks` off and `settings_checks` on leaves `token.default_write` running; the reverse leaves it off. Pinned in Task 3.
5. The controller test makes no request that is not a `GET` and none that is not in `KennelEndpoints`, with every switch on. Pinned in Task 1 and Task 3.

**Interfaces:**
- Produces, as proposals the slice may adjust:
  ```go
  // KennelSettingsReader is optional; a client without it gives `unavailable`.
  type KennelSettingsReader interface {
      KennelRepositorySettings(ctx context.Context, repo string, private bool) (*KennelSettings, error)
      KennelBranchProtection(ctx context.Context, repo, branch string) (*KennelProtection, error)
  }
  type KennelSettings struct {
      DefaultTokenWrite bool   // default_workflow_permissions == "write"
      ForkApproval      string // the policy word GitHub sends, for the weak-policy rule; "" for a private repository
      PrivateForkRuns   bool   // private repositories only: fork pull requests run workflows
      PrivateForkSecrets, PrivateForkWriteToken bool
  }
  type KennelProtection struct {
      Required []RequiredCheck // pinned to the Actions app only
      Unpinned int             // required, with no app or another app: counted, never judged
      Partial  bool            // one of the two halves could not be read
  }
  const GitHubActionsAppID = 15368
  ```
- Produces: `KennelEndpoints` gains `actions/permissions/workflow`, the two fork-policy paths, `branches/{b}/protection` and `rules/branches/{b}`. The base `actions/permissions` endpoint is **not** read: no finding uses it, and the list of what Kennel Club may call should hold only what it needs. Appendix A of the record lists it and is corrected in the documentation slice.

- [ ] Reads: `GET .../actions/permissions/workflow`, `.../permissions/fork-pr-contributor-approval` (public only), `.../permissions/fork-pr-workflows-private-repos` (private only), `GET .../branches/{b}/protection`, `GET .../rules/branches/{b}` (paginated). Use the typed go-github calls.
- [ ] Failure mapping: 403 is `ErrForbidden` and `denied`; a 404 on a settings route is `ErrNotFound` and `unavailable`; a 405 is `unavailable`, mapped here and not in `classify`; `ErrBranchNotProtected` is read before `c.fail` and is an empty classic half, not an error. Rulesets and classic are both read before the result is complete; one failing makes `Partial`.
- [ ] Fake: routes for the six endpoints; settings the test can set; protection (with the 404), required checks with `app_id` and rulesets with `integration_id`; the Administration gate answers 403 "Resource not accessible by integration" like `canReadActionsLocked`; an unregistered path still 404s.
- [ ] Tests: each endpoint returns what the fake holds; the 404, 403 and 405 cases; pagination of rules; a branch name with a slash; the allow-list tests run the new reads and fail on a non-`GET`; `Requests()` for a public and a private repository differ exactly by the one endpoint each side owns.
- [ ] *Mutation checks:* treat the protection 404 as `unavailable`; read only rulesets; read only classic; judge a check whose app is nil; treat 405 as `error`; call the private-fork endpoint on a public repository; drop the pagination; make a write request.
